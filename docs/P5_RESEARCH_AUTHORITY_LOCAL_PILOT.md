# P5.1–P5.2 independent research authority local pilot

This is **an offline/local pilot only**, not a production enablement.
The existing BRAIN research driver still refuses the
--research-catalog profile before it reads credentials. A passing local
pilot does **not** authorize BRAIN Catalog reads, paid LLM requests,
Simulation POST or Alpha submission.

## Architecture and security

1. A *separate process* runs the opt-in loopback-only authority server,
   with its **own signing keys and operator trust**. A single SQLite file
   stores committed Grant consumption, signed receipts, revocations,
   immutable global/per-Grant spend limits and attempts.
2. The service refuses every operation without a long per-role bearer token:
   ordinary token for Grant consumption/readback/budget reservation/snapshot;
   a distinct admin token for revocation. It binds **only 127.0.0.1**, has
   strict 64 KiB JSON envelopes and does not echo private errors or credentials.
3. A signed operator Grant and its exact handoff are validated server-side.
   A Grant and its operator approval can be consumed only once. Concurrent
   callers cannot successfully consume the same Grant; a timeout is
   **unknown until ledger readback**, not an invitation to retry.
4. The service signs its ledger readback with a **different key** from its
   consumption ACK. This demonstrates the contract but does not, merely by
   using different keys, prove independent organizational custody.
5. The service calculates a prospective model budget from the **signed**
   token/rate ceilings, not an amount supplied by the caller. An atomic
   SQLite transaction checks the consumed Grant ACK, Task ID, revocation,
   expiration, immutable per-Grant caps, and global cross-Grant ceiling.
   Unknown/unreconciled work retains reserved capacity.
6. The P5.2 driver audit revalidates operator signature, consumption ACK,
   ledger readback signature, driver session signature and exact Task scope
   on every proposed read frame. No executable BRAIN driver handle or
   permission is created.

The client has **no automatic retry** for consumption or reservation.
Neither this pilot nor an audited signature authorizes SDK dispatch.
Real provider tokenization, billed costs, trusted session identity,
remote recovery and production Canary remain unprovisioned.

## Locally launch the isolated authority service

Provision your own Ed25519 PKCS8 PEM keys with *separate* custody for
the operator, consumer and ledger readback. Never commit key files, operator
receipts, access tokens or local databases. On POSIX the service refuses
consumer/ledger private keys whose permissions are wider than owner-only
(0600). On Windows, arrange private-key ACLs separately: this pilot does
not attest ACL security. Keep the database outside the repository.

Create a JSON config such as this, substituting **absolute file paths**
for all path fields:

```json
{
  "schema_version": 1,
  "database_file": "/absolute/private/pilot-authority.sqlite3",
  "operator_trust_file": "/absolute/private/operator-trust.json",
  "consumer_private_key_file": "/absolute/private/consumer-key.pem",
  "ledger_private_key_file": "/absolute/private/ledger-key.pem",
  "consumer_id": "consumer",
  "consumer_key_id": "consumer-key-1",
  "ledger_id": "research-ledger",
  "ledger_issuer_id": "separate-ledger",
  "ledger_key_id": "ledger-key-1",
  "global_max_usd_micros": 1000000
}
```

The operator trust file uses the existing
**research_only_admission.py** Ed25519 issuer trust schema, with
schema_version=1, issuers, and revoked_grants. It is an externally
provisioned input, **not** generated by the Agent.

Inject **distinct high-entropy credentials** using the deployment
environment or a secrets manager; never provide them on CLI flags:

```bash
export ALPHA_RESEARCH_AUTHORITY_API_TOKEN="$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')"
export ALPHA_RESEARCH_AUTHORITY_ADMIN_TOKEN="$(python3 -c 'import secrets;print(secrets.token_urlsafe(48))')"

python3 -m alpha_research.orchestration.research_authority_server \
  --config /absolute/private/authority-pilot.json \
  --port 8765 --enable-local-pilot
```

The service exposes only its localhost health endpoint without auth:

```bash
curl --fail http://127.0.0.1:8765/healthz
```

The authenticated endpoints are **POST-only** with application/json
and the appropriate Bearer token:

| Path | Role | Behavior |
| --- | --- | --- |
| /v1/grant/consume | API | Verify signed Grant/handoff and write one unique consumption ACK |
| /v1/grant/readback | API | Sign Task-bound immutable ledger observation; rejected after revocation |
| /v1/spend/reserve | API | Task/ACK-bound atomic budget reservation, no SDK invocation |
| /v1/spend/snapshot | API | Read a consumed Grant's committed usage |
| /v1/spend/quarantine | API | Mark an ambiguous attempt UNKNOWN permanently; keep budget committed |
| /v1/spend/operation | API | Persist unique SDK-reported operation ID after reservation |
| /v1/spend/attempt | API | Read Task-bound attempt status after restart/revocation |
| /v1/spend/reconcile | Admin | Append independently signed observation without settling spend |
| /v1/grant/revoke | Admin | Revoke Grant; no new reservations or readback |
| /healthz | Anonymous localhost | Liveness only; no authority |

Responses deliberately contain **permission_to_dispatch=false**.
A remote transport should use TLS/mTLS and independently authenticated
service identity; **do not forward the pilot port over an untrusted
network, and do not add live SDK or BRAIN calls to this server**.

For P5.4 only, the authority config may include an optional
`recovery_trust_file` with an absolute path to independently configured
Ed25519 public-key trust. It never enables real provider access. See
[P5.4 recovery contract](P5_4_REMOTE_RECOVERY_AND_AUDIT.md).

## P5.2 Driver boundary

Use the driver-side function
**alpha_research.integrations.brain.driver.inspect_research_catalog_evidence_frame**
to audit signed read-only frame eligibility. It checks a full cryptographic
provenance chain, then applies exact Catalog scope and Optimization source
Alpha restrictions. The response is **DRIVER_READ_FRAME_POLICY_VALIDATED_NO_LIVE**
for a well-formed, permitted read frame or **DRIVER_READ_FRAME_DENIED**
otherwise. Both return **brain_read_authorized=false** and
**permission_to_dispatch=false**.

The actual --research-catalog runtime option is still fail-closed.
Opening it requires future independently reviewed driver-bound service
authentication and a supervised live read-only Canary.

## Offline validation

Run the entire P5.1/P5.2 integration suite using the existing
test discovery, with no real BRAIN, paid model or internet services:

```bash
python3 -m unittest discover -s tests -p 'test_p4_research_final_release.py' -v
python3 -m unittest discover -s tests -v
```

The integration tests bind a temporary service on **127.0.0.1 only**,
then dispose of the server and local SQLite databases. The tests include
credential refusal, signed ACK and ledger verification, duplicate JSON
refusal, consumed-once Grant, cross-Task protection, overspend, replay,
revocation, private-key separation and blocked BRAIN driver admission.

## Production blockers after P5.2

Independent issuer/key custody, true remote identity and TLS/mTLS,
external operator consent, model tokenizer and provider billing price
attestation, provider-enforced budget ceilings, remotely reconciled
outcomes and supervised Canary approval remain unverified. Simulation
and Alpha submission must get separate explicit authorization.
See RESEARCH_RUNTIME_OPERATOR_GUIDE.md for the current negative-only
production release gate and how to inspect a Task.
