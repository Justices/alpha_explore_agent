## 1. 引言

### 1.1 目的

本文档定义 nastu_quant —— 一个在 WorldQuant BRAIN 平台上自主探索
Alpha 的 Agent 系统 —— 应满足的全部需求，包括它必须完成的研究
流程、必须遵守的门禁与纪律、与用户和平台的交互方式，以及判定
实现是否合格的历史验收标准。现行研究规则按文首当前口径执行；
同时，文档中关于运行效果的口径为对外材料（包括设计大赛参赛帖）
提供真实、可核查的素材标准。

### 1.2 背景

本系统源于一套已经实际运行的研究实践：用户与通用 Agent 按文档
流程操作 BRAIN 平台，先后完成 20 余个研究批次。该实践证明流程
本身有效，但其中依赖 Agent 自觉的环节两次出现事故（见参考依据
R5）：一次在表达式中使用了被明令禁止的 `+` 拼接，一次跳过 RA
检查直接进行了相关性查询。两次事故的共同点是：规则写在文档里，
但没有任何机制阻止违规发生。

本项目要解决的正是这一点：把这套研究流程固化为一个职责、门禁
与状态都显性化的 Agent 系统 —— 规则不再依赖执行者自觉，而是
由流程结构本身保证。系统的研究目标、纪律与判定标准全部继承
现行实践（R2、R3），本文件负责把它们写成可设计、可实现、可
验收的需求。

### 1.3 术语

下列术语沿用现行研究流程（R2）的定义，本文不另立：

- **Candidate**：通过全部门禁（见 4.10）的 Alpha，计入产品目标。
- **RA Gate**：对 Alpha 的提交检查项集合及其失败计数判定环节。
- **预登记**：模拟执行之前落盘锁定的假设、表达式与判定标准文件。
- **探针**：字段探索阶段用于测绘字段行为的诊断性模拟。
- **先验**：由历史批次证据沉淀的、可复用于后续研究的结论库。
- **scope**：研究的参数边界（region / universe / delay / 回测设置）。

## 2. 总体描述

### 2.1 产品目标

nastu_quant 在锁定的研究 scope 内，自主完成从数据集选择到
Candidate 判定的完整研究链。**产品目标以产出 Candidate 的数量
衡量：3 个通过全部门禁的 Candidate。** 全程合规、可审计、可
恢复是达成该目标的底线条件而非目标本身：未达标时系统如实报告
缺口，不通过降低标准、放宽门禁或美化口径来凑数。Alpha 的提交
永远由用户人工完成，不属于本系统职责（见 2.2）。

### 2.2 范围与边界

**范围内：**

- 单个 BRAIN 账户、单一平台上的 Alpha 研究全链；
- 研究知识与先验的维护；
- 与用户的汇报、审批与急停交互。

**范围外：**

- Alpha 的自动提交（系统在能力层面不具备提交功能，见 4.2）；
- 未经用户批准的 scope 变更；
- 多账户、多平台与实盘交易；
- 参赛帖等对外材料的自动发布（由用户确认后人工或半自动完成）；
- 对同账户其他自动化的调度与管控（只检测与避让，见 4.14）。

**锁定的 scope（现行值，以 R2 与显式配置为准，见 5.5）：**
GLB / TOP3000 / Delay 1；decay 0；neutralization MARKET；
truncation 0.08；pasteurization ON；样本内区间 2014–2023 年。

#### 2.2.1 数据集的选择与锁定

数据集是研究的基本单元，其选择规则如下，且手动与自主两种
选集方式的锁定规则**不对称**：

1. **自主选集**：Agent 在平台 live 数据集范围内，依准入流程
   （4.3）自主选定数据集，无需逐个报批。
2. **手动选集**：用户可手动指定数据集。一经选定（无论手动
   还是自主），当前研究即锁定于该数据集：Agent 不得中途换集，
   不得以结果不佳为由自行跳集逃避证伪。
3. **手动选集的解锁**：仅两种情形——该数据集的当前研究完成
   归因，或用户明确解除/改派。
4. **自主选集的换集**：允许，但条件二选一——
   - **穷尽**：该数据集已无足够依据支持新的预测机制。穷尽须有
     证据条目：核心字段的假设空间已按预登记的证伪标准覆盖且
     全部证伪，或探针层面整集不通过。单纯结果不好不构成穷尽；
   - **用户命令**：收到用户明确的换集指令。

### 2.3 用户与角色

- **用户**（唯一）：BRAIN 顾问本人。角色是审批者（scope 变更、
  授权模式设定与切换）、scope 制定者，以及 Alpha 的最终提交者。
- **Agent**（本系统）：研究执行者，负责研究链的全部执行工作。
- **BRAIN 平台**：外部系统，研究执行与结果的来源。
- **同账户其他自动化**：用户自行运行的其他工具，不属于本系统
  组件；本系统须与之共存（见 4.14、5.4）。

### 2.4 运行环境

系统运行于 Muse harness 与本地工作区之上，文件系统即状态层
（研究状态全部落盘，见 5.1）；平台访问经 cnhkmcp 提供的接口层
（见 4.1、6.1）。平台会话寿命约 22 小时，会话管理见 4.1。
运行环境可能被杀或重启，系统须能从落盘状态恢复（见 5.1）。

### 2.5 硬约束

以下约束不可协商，任何设计与实现不得突破：

1. **研究铁律**：单个 Alpha 只用单个数据集、至多 3 个字段、
   operator_count < 8；禁用 trade_when、add、multiply 算子；
   禁用 `+`、`*` 拼接分支；假设与判定标准必须预登记；RA 检查
   先于相关性检查。
2. **凭证安全**（本条仅适用于本系统的需求口径，现行人工操作
   流程不在此列）：凭证文件由用户维护在项目目录之外，其路径
   作为环境参数提供给系统；系统只按路径读取，不得把凭证文件
   或其内容复制进项目/工作区；凭证内容不进记忆、不进日志、
   不出现在任何汇报与产物中。会话 cookie 保存在项目内（权限
   0600），cookie 无效时才动用凭证文件（见 4.1）。
3. **诚实口径**：一切运行效果只报实测；估计值、设计预期与
   目标值不得冒充实测数据（见 5.6）。

### 2.6 假设与依赖

- 平台 API 的行为与现行一致；
- 用户的审批响应时间不作保证，系统须能在等待审批时安全挂起；
- 用户提供的凭证文件持续有效；失效时由用户更新，系统按 4.1
  的失败处理挂起并报告。

## 3. 研究流程总览

本章给出研究主链的整体形态，后续各章逐项定义。主链由十个
阶段组成，按批次顺序串行推进（见 4.8）：

1. **选集**：按 2.2.1 的规则确定本轮研究的数据集；
2. **准入**（4.3）：先在平台验证数据集 live，再核验字段目录；
3. **字段探索**（4.4）：以探针测绘核心字段行为，产出探针报告、
   设计约束与准入判定；不通过则止步于此；
4. **假设**（4.5）：基于字段行为与经济机制提出假设，每个假设
   带有预期符号与证伪标准；
5. **预登记**（4.6）：把假设、表达式清单与判定标准落盘锁定；
6. **静态验证**（4.7）：逐条表达式过验证器，REJECT 不得执行；
7. **批次执行**（4.8）：提交模拟并等待结果，异常时先找回再
   回退，全程不产生重复提交；
8. **结果归因**（4.9）：结构化提取指标、分类，并逐条回判假设
   的支持/证伪；
9. **门禁判定**（4.10）：对达到 Sharpe 门槛的 Alpha 依次执行
   RA Gate 与相关性检查，顺序不可交换，全过者授予 Candidate；
10. **记忆回写**（4.11）：把本批证据写回先验库与禁止重跑
    清单，供后续批次与选集复用。

贯穿主链的横切机制：认证与会话维持执行通道（4.1、4.2）；
授权模式决定每个批次的启动方式（4.12）；进度播报让用户随时
掌握长任务状态（4.13）；流量归因区分本系统与外部自动化的
产物（4.14）；运行计量为效果汇报提供实测来源（4.15）。

## 4. 功能需求

### 4.1 认证与会话（FR-01，P0）

系统与平台之间的会话按两级机制维持与恢复：

1. **cookie 优先**：会话 cookie 保存在项目内（权限 0600）。
   系统启动与会话失效时，先用 cookie 恢复会话。
2. **凭证文件重连**：cookie 无效时，才读取用户提供的凭证
   文件自动重新认证，并刷新 cookie。凭证文件的存放与读取
   遵守 2.5 的凭证安全约束。
3. **失败处理**：两级均失败时，系统挂起当前工作、落盘状态
   并向用户报告（标记 needs_auth），等待用户处理；不得猜测
   凭据，不得循环重试。
4. **会话共享**：cookie 不绑定单一进程，本系统各组件共用
   同一会话；任一组件发现会话过期，即按上述流程重连。

### 4.2 能力白名单（FR-02，P0）

系统对平台的全部调用只允许经白名单内的能力发起。红线：
**提交类能力不得列入白名单**，即 Alpha 提交在本系统能力
层面不存在，而不是靠流程约定避免。白名单的具体清单属于
设计阶段产出；需求层只锁定本机制与上述红线。

### 4.3 数据集准入（FR-03，P0）

每个数据集进入研究之前必须通过准入，准入的顺序固定：

1. **先验证 live**：第一步在平台核验该数据集真实存在且
   可用；不存在或不可用即终止，不做后续工作。社区资料、
   历史清单与目录描述都不能替代这一步（社区数据 vintage 与
   live 平台不一致是已有实测教训，见 R5）。
2. **再核验字段**：拉取字段目录逐项核对；目录描述与实际
   字段冲突时，以字段为准。
3. 准入结论与证据落盘，作为后续字段探索的输入。

### 4.4 字段探索（FR-04，P0）

准入通过后、提出假设之前，系统必须对核心字段执行探针
探索，包含四个不可省略的产出：

1. **六项探针**：按官方 Understanding Data 协议对核心字段
   逐个执行探针（名义覆盖、零填充检查、不同窗口的变化率
   等）。探针使用诊断性设置（Neutralization=None）；探针
   产生的 Sharpe 仅是诊断副产品，不构成研究结论。
2. **探针报告**：探针的原始结果与读数落盘成报告。
3. **约束翻译**：探针结论必须被翻译为对后续设计的明确
   约束（例如字段的变化窗口下限、近重复字段的取舍、快而
   稀疏字段的平滑与子宇宙要求），假设与表达式设计必须服从
   这些约束。
4. **准入判定**：对字段与数据集给出 ADMIT 或 REJECT 及理由。
   REJECT 即止步，不进入假设阶段；被探针证据否定的假设在
   此层终止，不得带入预登记（除非有新的探针证据）。

### 4.5 假设管理（FR-05，P0）

1. **假设四要素**：每个假设必须包含经济机制（该字段为何
   应能预测收益）、预期符号、结构与窗口理由（服从 4.4 翻译
   出的约束），以及证伪标准（出现何种结果即判定该假设
   不成立，事先写明）。
2. **方向来源纪律**：预期符号只能来自 live 字段描述与
   经济机制推导。社区先验、他人结论、历史 vintage 数据
   不得作为方向依据。
3. **顺序**：先有假设清单，再把假设翻译为表达式；不允许
   先拼表达式再倒编机制解释。

### 4.6 预登记锁定（FR-06，P0）

1. **时机与内容**：任何模拟提交之前，预登记必须先落盘，
   内容包含假设清单、表达式清单与逐条判定标准。
2. **只写一次**：预登记落盘即锁定。模拟开始之后，不得
   修改判定标准。
3. **变更的代价**：需要变更假设、表达式或标准时，正确
   做法是本批作废、以新的预登记重开一批；作废的预登记与
   已产生的结果保留归档，作废原因必须写明，审计链不断裂。
4. **例外**：不影响判定的文字修订可以进行，但必须留下
   修订记录。

### 4.7 表达式静态验证（FR-07，P0）

每条表达式在进入执行队列之前，必须先通过本地静态验证，
裁决结果为 PASS、WARNING 或 REJECT（附拒绝码），规则集
至少覆盖：

- 语法解析失败；
- 未知算子，或禁用算子（trade_when、add、multiply）；
- 未知字段、混合多个数据集、字段数超过 3；
- operator_count ≥ 8；
- 二元 `+` 或 `*` 拼接；
- VECTOR 字段未经 vec 算子适配；
- 分组参数非法；
- 以 vec_ 算子或纯时序变换（ts_zscore、ts_rank 除外）结尾。

**受控例外**：同一数据集内两个字段之间的差或比默认拒绝；
仅当预登记中写明其自然经济意义的理由时才放行，放行必须
留下警告与理由痕迹。

REJECT 的表达式在系统中没有任何路径可以进入执行队列。
全部裁决结果随批次产物落盘，可审计。

### 4.8 批次执行与恢复（FR-08，P0）

1. **串行执行**：研究按批次顺序进行，一批完成（含归因）
   后才开下一批，不跨数据集并行。
2. **提交方式**：优先使用 multisim 批量提交。
3. **找回优先**：multisim 超时或子模拟未出现时，禁止直接
   重提；先按找回协议去平台侧对账（按时间窗与表达式查
   已生成的 Alpha），找回的结果直接接管进入归因；确认
   平台侧确实不存在的，才允许单条回退提交。全程同一
   表达式在平台侧只出现一次。
4. **可续跑**：进程被杀或环境重启后，按 5.1 从落盘状态
   恢复本批进度并继续，不重复已完成的步骤。

---

### 4.9 结果归因（FR-09，P0）

1. **结构化提取**：每条 Alpha 的 Sharpe、Fitness、Turnover
   及分区域、分年度指标，从平台原始返回中提取为结构化
   记录落盘，不依赖人工读数或记忆转述。
2. **四分法分类**：每条结果归入 metrics_pass、weak、failed
   或技术错误之一。平台 ERROR 属于技术错误，单独成类：
   不计为 Alpha 失败，也不进入假设的证伪判断。
3. **回判假设**：归因必须回到 4.5 的假设与预登记的证伪
   标准，逐条给出支持、证伪或证据不足的判定，而不只是
   罗列指标数字。
4. **汇报顺序**：向用户的汇报先报失败项与未通过的检查，
   再报通过项。

### 4.10 RA Gate 与相关性（FR-10，P0）

Candidate 的授予按以下固定顺序判定，顺序由系统结构保证，
不依赖执行者自觉：

1. **门槛**：Sharpe ≥ 1.58 者才进入 RA 检查；
2. **RA Gate**：按现行流程（R2）的检查项计算 RA fail count
   （含 fitness、2Y Sharpe、分区域 Sharpe 等）；
3. **失败即停**：fail count > 0 立即终止该 Alpha 的判定，
   标记为 RA-FAILED；系统在此状态下不存在对其发起相关性
   检查的路径；
4. **相关性检查**：仅 fail count = 0 者可查 production
   correlation 与 self correlation，两者实测值均须严格
   **< 0.70**；
5. **两两去重**：与每个既有 Candidate 的两两相关均须
   **< 0.40**。全部满足才授予 Candidate。

阈值口径说明：production/self 相关原口径为 ≤ 0.70，
现收紧为严格小于；任一相关性实测值不小于对应阈值，
即不得授予 Candidate（另见验收 A7）。

### 4.11 记忆与先验（FR-11，P1）

1. **逐批回写**：每批归因完成后，把结果、假设判定与
   字段行为结论写回先验库；后续批次与新数据集的设计
   必须先查先验。
2. **跨批模式**：跨数据集反复出现的规律沉淀为可复用
   先验（例如「变化优于水平」对哪类字段成立、对哪类
   不成立）。
3. **作废留痕**：先验结论被新证据推翻时，不删除原结论，
   而是标记作废并注明被何证据、于何时推翻，防止作废
   结论日后被重新当作依据。
4. **禁止重跑清单**：维护「已证伪 / 已穷尽」清单，粒度
   细到数据集 × 机制；选集与假设阶段必须先查此清单。
   2.2.1 所述穷尽的证据条目即落在此清单中。

### 4.12 人类审批与急停（FR-12，P0）

1. **授权模式**：批次执行的授权模式由用户选择，**默认为
   自动授权**：
   - 自动授权：批次模拟无需逐批批准，系统在锁定 scope 内
     连续推进研究，直至达标、数据集穷尽或被用户喊停；
   - 逐批批准：每个批次提交模拟之前，必须等待用户明确
     批准。
2. **不受模式影响的事项**：scope 变更永远需要用户批准；
   Alpha 提交永远不自动执行（且能力上不存在，见 4.2）。
3. **急停**：用户喊停后系统立即停止发起任何新模拟，
   已提交至平台侧的模拟不再干预，当前状态完整落盘。
4. **模式切换**：只能由用户操作，且每次切换留痕。
5. 批准的构成要件见 6.2：须有用户的明确肯定信号。

### 4.13 进度播报（FR-13，P1）

1. **时机**：长任务（探针队列、multisim 等待、整批回测）
   的关键节点——启动、阶段完成、异常、恢复、结束——
   系统主动向用户播报，不等用户询问。
2. **内容**：正在执行的事项、已完成进度、当前卡点，以及
   拟采取的下一步动作（如转入找回协议）。异常（超时无
   输出、会话失效等）须第一时间报告。
3. **性质**：播报是单向通知，不需要用户回应即可继续；
   它是自动授权模式下用户实施监督的主要渠道，急停
   （4.12）随时可用。

### 4.14 流量归因（FR-14，P1）

同一账户上可能同时存在用户自己的其他自动化。本系统须：

1. **登记标记**：本系统提交的每个 Alpha 在台账中登记
   所属批次与表达式，使账户内产物可区分来源；
2. **识别陌生流量**：盘点时发现不属于本系统的 Alpha
   活动，不将其归因于本系统，也不把本系统的产物遗漏；
3. **处置**：发现来源不明的活动时，暂停相关判断并报告
   用户，等确认来源后再继续；不干扰、不删除、不管理
   外部自动化。

### 4.15 运行计量（FR-15，P1）

系统按批次记录运行计量：时长、模拟数，以及可获得时的
token 消耗，作为运行效果汇报的实测来源（见 5.6）。
某计量项不可获得时，必须在汇报中明示「未统计」，不得
以估计值填充。

## 5. 非功能需求

### 5.1 可恢复性（NFR-01）

研究状态全部落盘于产物文件，不依赖进程内存。任意进程
被杀或环境重启后，系统从落盘产物恢复到最近一致状态，
与平台侧对账后从断点继续（与 4.8 的找回协议配合）。

### 5.2 可审计性（NFR-02）

每个对外结论——汇报中的每个数字与每个判定——都必须能
回溯到一份落盘产物（探针报告、预登记、结果记录、
RESULTS 等）。一个 Candidate 的授予须能完整回溯其链条：
表达式 → 验证裁决 → 预登记 → 平台原始结果 → RA 计算 →
相关性数值。作废与推翻的历史同样可查（见 4.6、4.11）。

### 5.3 安全性（NFR-03）

凭证文件位于项目之外、路径经环境参数注入、系统不复制
进项目（见 2.5）；会话 cookie 保存在项目内且权限受控
（0600）；任何日志、播报、汇报与对外材料中不得出现凭证
内容或 cookie 值，引用前先脱敏。

### 5.4 配额礼仪（NFR-04）

系统尊重平台的并发与频率限制：遭遇限流时退避等待，
不得以重试放大请求量。找回优先于重提（4.8）同时是
配额纪律。同账户共存其他自动化时，请求节奏留有余量，
不抢占、不挤兑。

### 5.5 可配置性（NFR-05）

scope、门禁阈值、探针窗口档等关键参数集中为显性配置，
不散落于代码或对话约定。配置变更分级：scope 类变更
须经用户批准；其余变更须留痕（操作者、时间、内容、
原因）。任一历史批次所用的配置须可回溯。

### 5.6 诚实口径（NFR-06）

一切对外数字必须可溯源到实测产物；无数据时明示
「未统计」或「不适用」，不留空、不编造。本条是 4.15
计量的目的所在，也是对外材料（参赛帖等）的硬性约束：
以估计冒充实测的参赛材料会使作者被列入黑名单。

### 5.7 产物命名规范（NFR-07）

研究产物按目录层级 `{region}/{delay}/{universe}/{datasetid}/`
组织，文件名格式为 `{时间}+{字段}.{文件格式}`。设计阶段
须按此口径落地；时间粒度、多字段拼接方式与文件格式
集合属设计阶段的细化项。

## 6. 接口需求

### 6.1 平台接口（IF-01）

系统与 BRAIN 平台之间只经 driver 这一层接口通信，形态
为 JSON-lines 逐行命令协议；上层逻辑不直接调用平台
API，认证、会话与限流处理收口于该层。接口可发出的
命令清单即 4.2 的能力白名单。具体命令签名与参数细节
属设计阶段（现行实现 R4 为参考）。

### 6.2 用户接口（IF-02）

系统与用户的交互经对话完成：进度播报、审批请求、急停
与授权模式切换均在对话中进行，不另设控制台。凡需要
批准的事项，必须有用户明确的肯定信号才生效；沉默、
未回复或含糊表态不构成批准，等待期间系统安全挂起，
不超时自动放行。

### 6.3 文件接口（IF-03）

每个批次的产物文件构成沿用现行四件套：探针报告、
预登记、结果 JSON、RESULTS.md，同目录归档。目录层级
与文件命名按 5.7 执行；现行批次目录在设计阶段迁移到
新规范。

## 7. 验收标准

下列场景全部通过，需求方视为达成。每项注明对应需求。

- **A1 表达式验证**（对应 4.7）：以违规表达式样本集逐条
  测试——含历史事故的 `+` 拼接式、禁用算子、混数据集、
  字段超限、operator_count 超限、VECTOR 未适配等——须
  全部被 REJECT **且拒绝码正确**；以合规表达式集
  （如 Batch 21 预登记的 E1–E8）测试，须全部 PASS。
  该测试集可自动重复执行，规则集每次变更后重跑。
- **A2 RA Gate 顺序**（对应 4.10）：以 RA 未通过的真实
  记录（如 Sharpe 1.64、RA fail count = 2 的历史 Alpha）
  测试：从任何入口尝试对其发起相关性检查，均须被结构性
  挡下；以 RA 通过的记录测试，相关性检查须能正常进行。
- **A3 找回协议**（对应 4.8）：复现 multisim 长时间无输出
  的故障形态：系统须先走找回协议对账，找回结果接管归因；
  全程同一表达式在平台侧只出现一次，故障经过完整落盘。
- **A4 会话恢复**（对应 4.1）：模拟会话过期：系统先用
  cookie 恢复；cookie 无效时用凭证文件自动重连并刷新
  cookie；人为使两级均失败时，系统挂起、标记 needs_auth
  并报告，全程无凭据猜测、无循环重试。
- **A5 中断恢复**（对应 5.1、4.8）：批次执行中途杀掉
  进程后重启：系统从落盘状态恢复，已完成步骤不重跑，
  平台侧已提交者经对账确认，最终产物与不中断跑完的
  等价（同一表达式集、同一判定标准、零重复 Alpha）。
- **A6 急停**（对应 4.12）：自动授权连跑中发出停止指令：
  以喊停时刻为界，其后平台侧新增 Alpha 数为 0；当前
  状态完整落盘，可支持事后恢复或复盘。
- **A7 相关性阈值**（对应 4.10）：对候选 Alpha 实测
  production/self 相关与对既有 Candidate 的两两相关，
  任一值不小于对应阈值（0.70 / 0.40，均为严格小于）
  时，系统不得授予 Candidate。
